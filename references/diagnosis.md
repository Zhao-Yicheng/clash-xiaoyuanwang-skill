# 诊断方法论：如何区分“CDN 入口 IP 被封锁”与其他节点故障

扫描脚本只有在**入口 IP 被 /32 精确封锁**时有效，先确诊再扫描。

## 五个判据（全部满足 = IP 级封锁）

1. **失败特征是 TCP SYN 超时**，不是 RST、不是 TLS 重置。
   `timeout 4 bash -c 'cat < /dev/null > /dev/tcp/<IP>/<端口>'`，超时(exit 124)=
   SYN 静默丢包；拒绝(exit 1)= 对端在线但拒绝，不是封锁。
   关键区分：“会话侦查”是先连上、跑一段后 TLS 被重置；IP 封锁是**握不上手**。
2. **tracert 在同一跳断掉**。`tracert -d -h 15 -w 1000 <IP>`，被封 IP 在进入
   国际出口之前(第 2 跳)就被丢包，正常 IP 能完整走到国际出口。
3. **同 /24 邻居可达**。网段封锁连坐整条街，单 IP 封锁只点名个别门牌。
   `.1/.2/.254` 全通、唯独自已被封的超时 = /32 精确封锁。
4. **被封 IP 从境外可达**（服务器没死）。经代理回连 80 端口拿到任意 HTTP 响应 =
   单向封锁。
5. **同一订阅在别的网络（手机 5G）正常**。排除机场服务端故障。

## 反证：不是封锁的常见情况

- **DNS 污染**：国内 DNS 给的 IP 本身就错，先做 DoH 对照（扫描脚本内置）。
  DoH 的 IP 可达 → 只是 DNS 污染，换 DoH/hosts 即可，不用本 skill。
- 服务器挂了：全网(含 5G、境外代理)都连不上 → 等机场修。
- 端口被封：同 IP 扫多端口排除。

## 为什么“换 IP 复活”成立

CF Anycast 同段众多 IP 都能服务同一 SNI，后端是同一台 Xray。验收链：

1. TCP 通
2. TLS 握手拿到**机场自有证书**(CN=机场域名) —— 排除“随便一台 CF”
3. 标准 WS 握手返回 **HTTP/1.1 101** —— Xray 接受该节点路径，决定性证据
4. (可选) 临时 mihomo 实例全链路实测 Google 204 + 出口归属

**裸 GET 不够**：Xray 对非 WS 请求返回 400，CF 边缘可能 403，403 会误导成“被拒”。
必须发带 `Sec-WebSocket-Key` 的真 WS 握手，看 101。
